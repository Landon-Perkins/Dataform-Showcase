# Documentation Index

This folder is the operating and architectural companion to the Dataform Showcase. It is designed to answer the core questions a hiring manager, peer reviewer, or stakeholder is likely to ask while scanning the repository.

## Documentation map

- [ARCHITECTURE.md](ARCHITECTURE.md) - layered design, data ownership boundaries, and model responsibilities
- [LINEAGE.md](LINEAGE.md) - source-to-staging-to-reporting flow across the showcase domains
- [STYLE_GUIDE.md](STYLE_GUIDE.md) - SQL conventions, readability standards, and transformation hygiene
- [TAGS.md](TAGS.md) - model metadata patterns for scheduling, domain ownership, and refresh cadence
- [QUICK_START.md](QUICK_START.md) - first-pass orientation for new reviewers
- [NAMING_CONVENTIONS.md](NAMING_CONVENTIONS.md) - naming strategy for schemas, models, and columns
- [GOVERNANCE.md](GOVERNANCE.md) - quality expectations, stewardship, and change management
- [OPERATIONS.md](OPERATIONS.md) - build, validation, monitoring, and operational troubleshooting
- [PORTFOLIO_GUIDE.md](PORTFOLIO_GUIDE.md) - what the repo demonstrates to hiring teams and stakeholders

## Why this documentation matters

This project is meant to read as a thoughtful analytics engineering portfolio, not as an unstructured internal workspace. These documents help explain:

- how the repo is structured
- how the architecture supports trusted models
- how lineage flows through the system
- how naming and metadata make the project easier to understand
- how operations and data quality are treated as first-class concerns

## Audience

This documentation is intentionally written to be readable by both technical reviewers and non-technical stakeholders. The project is built to signal strong analytical thinking while maintaining the technical depth expected from a senior analytics engineer.
